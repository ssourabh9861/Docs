# 11 — Coding / DSA (Google L5)

## 📕 LeetCode Revision Site → [`/docs`](../docs/)

A self-contained, tracker-driven revision site lives in [`../docs/`](../docs/). It renders
every problem from the **DSA tracker** spreadsheet with:

- problem statement, examples, and constraints,
- **multiple approaches** (naive → optimal) with idiomatic **Java 17** for each,
- solutions **hidden until you tap a card** (test recall first),
- solved/unsolved status and progress bars **synced from the tracker sheet**.

### View it

- **Locally:** `python3 -m http.server -d docs 8000` → open <http://localhost:8000>.
  (Open over a server, not `file://`, so `fetch()` can load the JSON/Markdown.)
- **GitHub Pages:** repo **Settings → Pages → Build from branch → `main` (or this branch) → `/docs`**.
  The site is static (`.nojekyll`), so it publishes as-is.

### Keeping status in sync with the tracker

Status comes from `docs/data/progress.json`, regenerated by
[`scripts/sync_tracker.py`](../scripts/sync_tracker.py). The **Sync DSA tracker** GitHub
Action ([`.github/workflows/sync-tracker.yml`](../.github/workflows/sync-tracker.yml))
regenerates and commits it — run it from the Actions tab (the site's **⟳ Sync now**
button links straight there) or let the daily schedule handle it.

To pull **live** from the sheet (not the committed snapshot), set a repository
**variable** `TRACKER_GID` to the numeric gid of the tracker's 3rd tab (open that tab; the
URL ends in `#gid=NNNNN`) and share the sheet as *Anyone with the link: Viewer*. Without
it, the workflow rebuilds from `scripts/tracker_snapshot.tsv`.

### Adding / editing a write-up

Each problem is one Markdown file at `docs/content/<topic-slug>/<problem-slug>.md`
(slugs match `progress.json`). Edit or add files there; the topic page renders them on demand.
